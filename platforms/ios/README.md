# Monarch for iOS

The SwiftUI implementation of the [Monarch](../../README.md) design system.
It shares tokens, colour roles, type roles and component vocabulary with
Monarch on the web and on Android. It looks like Monarch and behaves like iOS
([the rule](../../docs/guides/native-look-and-feel.md)). The architecture is
described in
[NATIVE-PLATFORMS.md](../../docs/architecture/NATIVE-PLATFORMS.md).

Status: unreleased. The version is the `@rookcom/monarch-react` version, in
the `0.14.x` patch series; the first native release ships with the next
patch. No Rook product ships on it yet, so the API has not been proven in
production and may change.

## Adding components

Adding a component only adds files; no shared file is edited. The inventory,
the compiled examples, the test fixture registry and the sample's navigation
are generated by `Scripts/generate.py` from per-component files. The recipe,
the conventions and a worked example are in
[docs/ADDING-COMPONENTS.md](docs/ADDING-COMPONENTS.md).

## Requirements

|                     | Version                                                                                       |
| ------------------- | --------------------------------------------------------------------------------------------- |
| Deployment target   | iOS 17.0                                                                                      |
| Swift tools version | 6.0                                                                                           |
| Swift language mode | 6 (complete strict concurrency)                                                               |
| Verified with       | Xcode 26.6 (17F113), Swift 6.3.3, iOS Simulator SDK 26.5, iPhone 17 Pro simulator on iOS 26.5 |
| Dependencies        | None                                                                                          |

iOS 17 is the minimum because the library uses `AccessibilityNotification`,
`Color.resolve(in:)` in its tests, the two-parameter `onChange`, and the
Observation framework in the sample. Versions other than the ones in the
"Verified with" row have not been tested.

The manifest also lists macOS 14. That is a build convenience so that
`swift build` and `swift test` run on a Mac without a simulator. macOS is not a
supported product, and nothing is tested for use in a Mac app.

## Installing

Swift Package Manager resolves a package by URL only when `Package.swift` is at
the root of the repository. The repository root has a `Package.swift`
generated from this folder's manifest (edit only `platforms/ios/Package.swift`;
a check fails when the two disagree), and each release is a plain `0.14.N`
git tag. Once the first release is tagged, add the repository URL in Xcode
(File > Add Package Dependencies) with "Up to Next Minor Version" from that
tag, or in another package:

```swift
.package(url: "https://github.com/RookHQ/monarch", .upToNextMinor(from: "0.14.6"))
```

and depend on `.product(name: "MonarchUI", package: "monarch")`. Until the
first tag exists, use a local checkout:

In Xcode: File > Add Package Dependencies > Add Local, and choose the
`platforms/ios` folder. Then add `MonarchUI` to the app target.

In another package:

```swift
dependencies: [
    .package(path: "../monarch/platforms/ios")
],
targets: [
    .target(
        name: "App",
        dependencies: [
            .product(name: "MonarchUI", package: "ios"),
            .product(name: "MonarchTokens", package: "ios"),
        ]
    )
]
```

For a local path dependency the package identity is the name of the folder,
`ios`. With XcodeGen, see `Sample/project.yml`.

## Getting started

Install the theme once at the root of the app:

```swift
import MonarchUI
import SwiftUI

@main
struct ExampleApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
                .monarchTheme()
        }
    }
}
```

`monarchTheme()` puts a `MonarchTheme` in the environment, follows Dark Mode
and Increase Contrast, and sets `tint` to the accent so that system controls
(`Toggle`, `Picker`, `ProgressView`, navigation bars) take the accent.

### Theme setup

Appearance has three independent inputs. Each defaults to the device setting
or the default accent.

```swift
import MonarchTokens
import MonarchUI
import SwiftUI

struct ThemedRoot: View {
    var body: some View {
        ContentView()
            .monarchTheme(
                scheme: .dark,                          // .system, .light, .dark
                contrast: .more,                        // .system, .standard, .more
                accent: MonarchTokens.Accents.neutral   // one of 21 accents
            )
    }
}
```

The inputs resolve to one of four themes: `light`, `dark`, `hc-light` and
`hc-dark`. The rule is a pure function, `MonarchAppearance.resolve`, and is
covered by tests. The modifier can be applied again lower in the tree to give
a subtree another appearance.

A product that bundles its own font passes the family name. Monarch bundles no
font files, and text still scales with Dynamic Type:

```swift
ContentView()
    .monarchTheme(typography: MonarchTypography(fontFamily: "Poppins"))
```

### Token usage

Views read the theme from the environment. Every colour role of the generated
tokens is available on `theme.colors` by name.

```swift
struct InvoiceRow: View {
    @Environment(\.monarchTheme) private var theme

    var body: some View {
        VStack(alignment: .leading, spacing: theme.spacing.space2) {
            Text("Invoice 1042")
                .monarchTextStyle(.bodyStrong)
                .foregroundStyle(theme.colors.textDefault)
            Text("Due in 3 days")
                .monarchTextStyle(.caption)
                .foregroundStyle(theme.colors.textMuted)
        }
        .padding(theme.spacing.space4)
        .monarchElevation(.sm, in: RoundedRectangle(cornerRadius: theme.radius.lg))
    }
}
```

| Value             | Access                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------- |
| Colour roles (96) | `theme.colors.bgCanvas`, `theme.colors[role: \.accentSolid]`                              |
| Type roles        | `.monarchTextStyle(.display)` … `.code`                                                   |
| Spacing           | `theme.spacing.space4`                                                                    |
| Radii             | `theme.radius.md`                                                                         |
| Elevation         | `.monarchElevation(.md, in: shape)`, `theme.elevation.layers(for: .md)`                   |
| Motion            | `.monarchAnimation(.fast, value: isOn)`, `theme.motion.animation(_:easing:reduceMotion:)` |
| Raw primitives    | `MonarchTokens.Space`, `MonarchTokens.Radius`, … in the `MonarchTokens` module            |

Do not read `MonarchTokens.light.colors` (or any other theme) directly in a
view. The view would not follow the scheme, the contrast setting or the accent.

## Components

`inventory/<id>.json` documents each component and each documented
native-adoption item: API, options, states, appearance, platform notes,
accessibility behaviour, edge cases and compiled examples. `components.json`
is generated from those files.

| Component                                      | Class | Use                                                                            |
| ---------------------------------------------- | ----- | ------------------------------------------------------------------------------ |
| `MonarchButtonStyle`, `MonarchButton`          | B     | `Button("Save") { }.buttonStyle(.monarch(.primary))`                           |
| `MonarchTextField`                             | B     | Label, helper and error over `TextField` or `SecureField`                      |
| `Toggle`                                       | A     | Standard switch, themed by the tint                                            |
| `MonarchCheckboxToggleStyle`                   | B     | `.toggleStyle(.monarchCheckbox)`                                               |
| `Picker`                                       | A     | Single choice. iOS has no radio button; Monarch does not add one               |
| `MonarchCard`                                  | B     | Padded surface with border, radius and elevation                               |
| `MonarchDivider`                               | B     | Standard `Divider` in the theme's border colour                                |
| `MonarchProgressViewStyle`                     | B     | `.progressViewStyle(.monarchLinear)`; the circular style stays native          |
| `MonarchIcon`                                  | B     | SF Symbols at 16, 20 or 24 points, decorative or labelled                      |
| `MonarchBadge`                                 | C     | Tones neutral, info, success, warning, danger; variants subtle, solid, outline |
| `MonarchBanner`                                | C     | Inline status with tone, title, message and one optional action                |
| Navigation, lists, sheets, menus, date pickers | A     | Standard SwiftUI                                                               |

Class A is native adoption (Monarch ships nothing), B is a style or thin
wrapper over a system control, and C is built by Monarch because the platform
has no equivalent.

```swift
struct CheckoutForm: View {
    @State private var email = ""
    @State private var wantsReceipt = true
    @State private var isSaving = false

    var body: some View {
        VStack(alignment: .leading, spacing: 16) {
            MonarchBanner(
                "Payment failed",
                message: "Check the card details and try again.",
                tone: .danger
            )

            MonarchTextField(
                "Email",
                text: $email,
                prompt: "name@example.com",
                helper: "We send the receipt here."
            )

            Toggle("Email me a receipt", isOn: $wantsReceipt)
                .toggleStyle(.monarchCheckbox)

            MonarchButton("Pay", variant: .primary, isLoading: isSaving, fullWidth: true) {
                isSaving = true
            }

            HStack {
                MonarchBadge("Paid", tone: .success)
                MonarchBadge("Draft", variant: .outline)
            }

            ProgressView("Uploading", value: 0.4)
                .progressViewStyle(.monarchLinear)
        }
        .padding()
    }
}
```

Component titles and messages are plain `String` values that the app has
already localised. The strings Monarch itself provides (spoken accessibility
text such as "Loading") are in one table per component under
`Resources/en.lproj/`, and the button and banner ones can be replaced through
`loadingLabel` and `toneLabel`.

### Time zones

A component parameter that takes a time zone is a Foundation `TimeZone`;
`nil`, or leaving the default, means `TimeZone.autoupdatingCurrent`, read each
time. A value that is stored or sent between processes, such as
`MonarchBusinessHoursValue.timeZone` or the slot picker's data, keeps the IANA
identifier as a `String`, as on the web and on Android.

### Accessibility

Each inventory entry lists the concrete behaviour. In summary:

- Touch targets are at least 44 by 44 points, also when the visible control is
  smaller (`monarchMinimumHitTarget()`).
- All text and icons scale with Dynamic Type, including the accessibility
  sizes. The tests render every component at the largest size.
- Layout uses leading and trailing edges. The tests render every component
  right to left.
- Increase Contrast selects the high-contrast themes. Reduce Motion removes
  the press, checkbox and indeterminate-progress animations.
- Styles keep the standard controls, so VoiceOver roles, values and gestures
  are the system's.

VoiceOver output has not been checked on a device in this iteration; see
"Known limitations".

### Experimental API

A declaration that is not yet stable is marked `@_spi(Experimental)` and is
visible only to a file that opts in with `@_spi(Experimental) import MonarchUI`.
Such declarations may change in any release, never appear in a stable
signature, are left out of the API baseline, and have
`"status": "experimental"` in the inventory.

### What the checks cover

- **Inventory.** `Scripts/generate.py` validates every `inventory/<id>.json`
  against `inventory/schema.json` and checks the conventions: a `build`
  entry has its source folder, a `build` or `style` entry has fixtures, a
  documentation-only entry has no Swift name, strings keys start with
  `monarch.`. `--check` fails if `components.json` or a generated Swift file
  is stale.
- **Lint.** `swift format lint --strict` with `.swift-format`. swift-format
  ships with the Swift toolchain, so nothing has to be installed. It requires
  a documentation comment on every public declaration. Generated files
  (`Sources/MonarchTokens` and every `Generated` folder) are not linted.
- **Tests.** Token tests (theme ids, `withAccent`), appearance resolution,
  colour mapping, shared internals, and per-component logic tests. The matrix
  test hosts every fixture of every component in all four themes, at the
  default and the largest Dynamic Type size, left to right and right to
  left. Fixtures are declared in each component's own test file and
  discovered by the generator. The Dynamic Type growth and touch-target size
  checks run only on the simulator.
- **Compiled examples.** The generator writes every `examples[].code` of the
  inventory into `Tests/MonarchUITests/Generated/Examples/`, one file per
  family. The tests compile and render each one in all four themes. The view
  examples in this README and in the DocC article are mirrored by hand in
  `Tests/MonarchUITests/Core/ReadmeExamplesTests.swift`.
- **Public API.** `Scripts/api.sh` dumps the public declarations from the
  compiler's symbol graph and compares them with `api/MonarchUI.txt` and
  `api/MonarchTokens.txt`. The baseline is updated once per merge by
  `Scripts/merge-check.sh`, not in working copies.
- **Warnings.** Host and simulator builds treat warnings as errors in
  `verify.sh`. The flag is passed on the command line, not set in the
  manifest, so it never affects an app that depends on the package.

## Known limitations

- Not installable by URL until the first `0.14.N` release is tagged (see
  "Installing").
- VoiceOver, Switch Control and Full Keyboard Access have not been tested on a
  device or with the Accessibility Inspector. The accessibility behaviour in
  the inventory describes what the code sets.
- There are no screenshot or snapshot tests. The rendering tests check that
  every component lays out and draws, not what it looks like.
- Native text fields, switches and spinners do not draw in SwiftUI's
  `ImageRenderer`, so for those the rendering tests rely on the layout pass
  in a hosting view.
- English strings only.
- Shadows ignore the token's spread value, because SwiftUI shadows have no
  spread.
- Line height is approximated: SwiftUI takes extra line spacing, so the
  modifier adds the difference between the token line height and 1.2 times
  the font size.
- `MonarchTextField` is single-line. There is no `TextFieldStyle`, because
  SwiftUI's `TextFieldStyle` protocol has no public requirement to implement.
- The banner does not announce itself when it appears.
- Poppins, the brand typeface on the web, is not bundled.
- The visible button heights (32, 36 and 40 points) are centred in a
  44-point touch target, so a button takes at least 44 points of layout
  height.
