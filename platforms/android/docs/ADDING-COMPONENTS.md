# Adding a component to Monarch for Android

This is the recipe for covering one entry of `platforms/parity.json` on
Android. Many people do this at the same time, each in a private copy of
`platforms/android`, and only their new files are copied back. So the first
rule is:

**Adding a component only adds files. You never edit a file that already
exists.**

Every list that would otherwise be shared (the inventory, the compiled
examples, the test fixture registry, the previews test, the catalogue's
navigation, the strings) is either one file per component, discovered by
walking the folders, or generated by Gradle into `build/`.

The iOS recipe is `platforms/ios/docs/ADDING-COMPONENTS.md`. The concepts and
the inventory schema are the same on both platforms.

## 1. Read the plan entry

Find the entry in `platforms/parity.json` by its `id`. You need:

| Field              | Use                                                                           |
| ------------------ | ----------------------------------------------------------------------------- |
| `id`               | The inventory file name, `inventory/<id>.json`, and the fixtures id.          |
| `family`           | The package and the folders (see the table below).                            |
| `title`            | The inventory `title` and the title of the catalogue page.                    |
| `android.coverage` | What you deliver: `build`, `style`, `native`, `compose` or `web-only`.        |
| `android.name`     | The Kotlin name. Use it exactly; iOS uses the same name where both build one. |
| `android.uses`     | The Compose or Material 3 API to build on.                                    |
| `dependsOn`        | Entries that must exist first. Use those components; do not rebuild them.     |

The family package is the web family in lower case without hyphens:

| `family`      | Package         | `family`     | Package        |
| ------------- | --------------- | ------------ | -------------- |
| actions       | `actions`       | identity     | `identity`     |
| billing       | `billing`       | intelligence | `intelligence` |
| charts        | `charts`        | interaction  | `interaction`  |
| collaboration | `collaboration` | layout       | `layout`       |
| crm           | `workflow`      | navigation   | `navigation`   |
| data-display  | `datadisplay`   | overlays     | `overlays`     |
| data-grid     | `datagrid`      | scheduling   | `scheduling`   |
| feedback      | `feedback`      | search       | `search`       |
| files         | `files`         | technical    | `technical`    |
| forms         | `forms`         | typography   | `typography`   |
| geo           | `geo`           | workflow     | `workflow`     |

## 2. The files you create

Below, `<Name>` is `android.name` (for example `MonarchBadge`), `<name>` is
that name without `Monarch`, in lower case (`badge`; `MonarchSwitchRow` gives
`switchrow`), `<family>` is the package from the table and `<id>` is the web
id. Paths are from `platforms/android`. `…` stands for
`kotlin/com/rookhq/monarch`.

### Coverage `build`, or `style` with a new Kotlin declaration

| #   | File                                                                                  | Required                                                                                               |
| --- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1   | `monarch-compose/src/main/…/components/<family>/<name>/<Name>.kt`                     | Yes. The public composable and its overloads. Package `com.rookhq.monarch.components.<family>.<name>`. |
| 2   | `monarch-compose/src/main/…/components/<family>/<name>/<Name><Option>.kt`             | One file per further public type (a variant or size enum).                                             |
| 3   | `monarch-compose/src/main/…/components/<family>/<name>/<Name>Tokens.kt`               | Yes if the component has any size, spacing or colour decision. An `internal object`.                   |
| 4   | `monarch-compose/src/main/res/values/strings_<name>.xml`                              | Only if the component has built-in text.                                                               |
| 5   | `monarch-compose/src/debug/…/components/<family>/<name>/<Name>Previews.kt`            | Yes. The previews.                                                                                     |
| 6   | `monarch-compose/src/test/…/components/<family>/<Name>Test.kt`                        | Yes. Fixtures and tests.                                                                               |
| 7   | `sample/src/main/kotlin/com/rookhq/monarch/sample/sections/<family>/<Name>Section.kt` | Yes. The catalogue page.                                                                               |
| 8   | `inventory/<id>.json`                                                                 | Yes. Documentation and compiled examples.                                                              |

### Coverage `style` that reuses an existing type

For example `spinner`, which is `MonarchProgress` in its circular,
indeterminate form. No source files.

| #   | File                                                               | Required                                                     |
| --- | ------------------------------------------------------------------ | ------------------------------------------------------------ |
| 1   | `inventory/<id>.json`                                              | Yes. `name` is the existing type.                            |
| 2   | `monarch-compose/src/test/…/components/<family>/<PascalId>Test.kt` | Yes. `object <PascalId>Fixtures` and `class <PascalId>Test`. |
| 3   | `sample/…/sections/<family>/<PascalId>Section.kt`                  | Yes.                                                         |

`<PascalId>` is the id in PascalCase: `menu-button` gives `MenuButton`. See
`inventory/spinner.json`, `components/feedback/SpinnerTest.kt` and
`sections/feedback/SpinnerSection.kt`.

### Documentation-only entries: `native`, `compose`, `web-only`

Monarch ships no Kotlin. The entry is the documentation.

| #   | File                                              | Required                                                                                                           |
| --- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 1   | `inventory/<id>.json`                             | Yes.                                                                                                               |
| 2   | `sample/…/sections/<family>/<PascalId>Section.kt` | For `native` and `compose`: yes, so the catalogue shows the Material 3 component in the theme. For `web-only`: no. |

Rules for these entries (`generateInventory` enforces the ones marked ✔):

- `name` is `null` ✔.
- `native`: `kind` is `native`, `category` is `A` ✔. `wrapsNative` names the
  exact API with its package, for example
  `androidx.compose.material3.ModalBottomSheet` ✔ (not empty). At least one
  example that uses that API ✔; it is compiled and composed inside
  `MonarchTheme` in all four themes. A catalogue page ✔.
- `compose`: `kind` is `recipe` ✔. `wrapsNative` names the Compose containers
  used, `dependsOn` lists the Monarch components the recipe is made of, and
  at least one example is the complete recipe ✔ (compiled and composed).
  `category` is `B`. A catalogue page ✔.
- `web-only`: `kind` is `none` ✔, `wrapsNative` is `null`, `examples` may be
  empty, `category` is `A`. `summary` says what the web component is,
  `platformNotes` says why it has no meaning in a native app, and `whenToUse`
  says what an Android app does instead.

## 3. What you must not touch

- `build-logic/`, every `build.gradle.kts`, `settings.gradle.kts`,
  `gradle.properties`, `gradle/libs.versions.toml`, `config/`, `README.md`,
  `CHANGELOG.md`, `docs/`, `inventory/schema.json`.
- Anything generated: `components.json` and everything under a `build/`
  folder. They change in your copy when you run Gradle; that is expected. Do
  not copy them back.
- `monarch-compose/api/` and `monarch-tokens/api/`. The API dumps are
  regenerated once, at merge. Do not run `apiDump`.
- `monarch-tokens/`. Generated from `packages/tokens`.
- `theme/`, `foundation/`, `accessibility/`, `internal/`, the test helpers in
  `src/test/…/testing/`, and every other component's folder, tests, page,
  strings and inventory file. If you need a shared helper that does not
  exist, keep it `private` or `internal` in your own folder and say so when
  you hand over; it is promoted to `internal/` at merge.
- `res/values/strings.xml` does not exist and must not: one file per
  component.

What you hand over is exactly the new files from section 2, and nothing else.

### Dependencies

Components use AndroidX, Compose and Material 3 only. These are already
dependencies of `monarch-compose`; use them freely:

| Artifact                                                                                                       | For                                                                                                                  |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Compose UI, Foundation (includes `HorizontalPager`, lazy lists and grids, drag and drop, `Canvas`), Material 3 | Everything                                                                                                           |
| `androidx.compose.material3.adaptive:adaptive`, `adaptive-layout`, `adaptive-navigation`                       | `currentWindowAdaptiveInfo()` and window size classes, list-detail and supporting panes                              |
| `androidx.compose.material3:material3-adaptive-navigation-suite`                                               | `NavigationSuiteScaffold`                                                                                            |
| `androidx.activity:activity-compose`                                                                           | `BackHandler`, `rememberLauncherForActivityResult` with `PickVisualMedia`, `OpenMultipleDocuments`, `CreateDocument` |

If a component seems to need anything else, **do not add it**. Build what you
can behind a slot or a callback, and report the artifact when you hand over.
The ones the plan is expected to raise, and the answer for each:

| Artifact                                        | Plan entry                        | What to do instead                                                                                     |
| ----------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `androidx.emoji2:emoji2-emojipicker`            | `emoji-picker`                    | Report it. Until it is decided, take the picker as a slot.                                             |
| `androidx.biometric:biometric`                  | `step-up-auth-dialog`             | Take an `onRequestBiometric` callback; the app owns `BiometricPrompt` (it needs a `FragmentActivity`). |
| `androidx.media3:media3-ui`, `media3-exoplayer` | `file-preview`                    | Take the player as a `@Composable` slot.                                                               |
| `androidx.core:core-telecom`                    | `incoming-call`                   | A `native` entry: the app posts the call notification.                                                 |
| `androidx.navigation:navigation-compose`        | none                              | Components do not navigate; they call back.                                                            |
| CameraX                                         | `pre-join-lobby`, `device-picker` | Take the camera preview as a slot.                                                                     |
| A chart library                                 | `charts` family                   | None: draw with Compose `Canvas`.                                                                      |
| An image loader (Coil, Glide)                   | any picture                       | Never. See [Images](#images).                                                                          |

A View through `AndroidView` is allowed only where `android.uses` in the plan
names a View (`android.webkit.WebView`). Otherwise stay in Compose.

`minSdk` is 24 and core library desugaring is off, so `java.time` (API 26)
does not compile clean: lint reports `NewApi`. A date or a time in a public
API is epoch milliseconds in UTC (`Long`), as in the Material 3
`DatePickerState`; format with `android.icu.text.DateFormat` or
`android.text.format.DateUtils`.

## 4. API conventions

### Material 3 first

1. If Material 3 has the component and it looks right in the theme, the
   coverage is `native`: ship nothing, document it.
2. Add a `Monarch<Name>` composable only when a wrapper adds value the theme
   cannot: variants and sizes, a label with helper and error text, a loading
   state, a fixed composition, merged semantics. It calls the Material 3
   component inside and passes Monarch colours, shape and type to it.
3. Build a custom component only when Material 3 has no equivalent. Build it
   from `foundation` layouts and the helpers in `internal/`.
4. Do not recreate a Material 3 component.

### Names and vocabulary

- The composable is `android.name`. Option enums are `<Name>Variant`,
  `<Name>Size`; their constants are PascalCase.
- Use the shared words and nothing else:
  - variants of actions: `Primary`, `Secondary`, `Ghost`, `Danger`; the
    default is `Secondary`
  - emphasis: `Subtle`, `Solid`, `Outline`
  - sizes: `Sm`, `Md`, `Lg` (no `xs` on touch)
  - tones: the existing `MonarchTone` (`Neutral`, `Info`, `Success`,
    `Warning`, `Danger`). Do not declare another tone enum.
- Booleans are adjectives or states without `is`: `enabled`, `loading`,
  `checked`, `selected`, `expanded`, `readOnly`, as in Material 3.
- State is hoisted: `value` with `onValueChange`, `checked` with
  `onCheckedChange`, `selected` with `onClick`. A component holds no state the
  app may need.

### Parameter order

The Compose API guidelines, in this order:

1. required parameters (data first, then event callbacks);
2. `modifier: Modifier = Modifier`, always present, always the first optional
   parameter, applied once to the outermost element;
3. optional parameters: `tone`, `variant`, `size`, then `enabled` and other
   state flags, then optional strings and slots, then string overrides, then
   `interactionSource: MutableInteractionSource? = null` for anything the
   user can press or focus;
4. a trailing `content` lambda, if the component has one.

Every optional parameter has a default. Compare `MonarchButton` and
`MonarchBadge`.

### Slots and strings

- Plain text the app supplies is a `String` that the app has already
  localised: `text`, `label`, `title`, `message`, `helperText`, `errorText`.
- Offer a slot (`(@Composable () -> Unit)? = null`) for icons, actions and
  anything the app may want to compose: `leadingIcon`, `trailingIcon`,
  `action`. Do not take an `ImageVector` where a slot works.
- When the main content can reasonably be more than a string, give two
  overloads: one with `text: String` and one with a trailing
  `content: @Composable <Scope>.() -> Unit` (see `MonarchButton`). The string
  overload calls the slot overload.

### Built-in strings

- Text Monarch supplies (a state description, a default label) is a resource
  in **your own file**, `res/values/strings_<name>.xml`, named
  `monarch_<name>_<key>`, with a comment above each string saying where it is
  used.
- Read it with `monarchString(override, R.string.monarch_<name>_<key>)`.
- Every built-in string can be replaced by a nullable parameter
  (`loadingLabel: String? = null`).

### Colours, sizes and shape

- Colours come from `MonarchTheme.colors` by role. Never
  `MonarchTokens.light…` or another token primitive, never `Color(0x…)`,
  `Color.Red`, `Color.White`, `Color.Black`, `Color.Gray`. `Color.Transparent`
  and `Color.Unspecified` are allowed: they are the absence of a colour.
- Never dim with alpha (`copy(alpha = …)`). Use the role that exists for the
  state: `textDisabled`, `bgMuted`, `borderSubtle`.
- Decide colours in a **pure function** in `<Name>Tokens.kt` that takes
  `MonarchColors` and the state and returns `MonarchSurfaceColors` or plain
  `Color`s, and test it in every theme.
- Sizes, spacing and radii come from `MonarchTokens.Space`, `.Control`,
  `.Radius` through constants in `<Name>Tokens.kt`, or from
  `MonarchTheme.spacing` and `MonarchTheme.shapes`. No `12.dp` and no
  `14.sp` in a component: `SourceRulesTest` rejects them.
- Text uses `MonarchTheme.typography` (or `MonarchText`). Never a literal
  font size.

### Layout, text size and motion

- Start and end only; never left and right. `Arrangement`, `PaddingValues`
  and `Alignment.Start` mirror for you; `offset(x =)`, `absolutePadding` and
  custom drawing do not.
- Directional icons mirror: an `ImageVector` with `autoMirror = true`, or
  `MonarchIcon(painter, …, mirrorInRtl = true)`.
- Material 3 `ListItem` places each slot (`headlineContent`,
  `supportingContent`, `leadingContent`, `trailingContent`) in a box, so two
  children passed to one slot are drawn on top of each other. Put several
  children in a `Column` or `Row` inside the slot.
- Nothing that contains text has a fixed height. Use `heightIn(min = …)`, let
  text wrap, and look at the fixture at font scale 2.0.
- Every element the user can tap has a touch target of at least 48dp by
  48dp, reserved in the layout. Material 3 controls do this themselves. For a
  custom element that is visibly smaller, put
  `Modifier.monarchMinimumTouchTarget()` before `clickable` or `toggleable`.
  The matrix test fails on a smaller target.
- Animate with `MonarchTheme.motion.spec(…)`, which becomes an immediate
  change when the user has removed animations. A repeating animation needs a
  still form: check `MonarchTheme.motion.reducedMotion`.

### Accessibility

- Keep the Material 3 component and you keep its role, state and actions.
- A row that acts as one control carries the interaction on the row:
  `Modifier.toggleable(value, role = Role.Checkbox, …)` or
  `Modifier.selectable(…)`, with the inner control given `null` for its
  callback, so there is one target and one TalkBack element (see
  `LabelledControlRow` and `MonarchCheckboxRow`).
- Set the role (`Role.Button`, `Checkbox`, `Switch`, `RadioButton`, `Tab`,
  `Image`) when you build the interaction yourself.
- State that is not a role goes in `stateDescription` ("Loading") or a
  semantics property (`selected`, `heading()`, `error(…)`,
  `progressBarRangeInfo`), not into the label.
- Group what is read together with
  `Modifier.semantics(mergeDescendants = true) { }` and keep actions as
  separate elements (see `MonarchBanner`).
- Announce what appears without focus moving with
  `liveRegion = LiveRegionMode.Polite`; `Assertive` only for an error that
  blocks the user. Make it opt-in when the component can also be on screen
  from the start.
- Decorative icons take `contentDescription = null`. Meaningful ones take a
  description; make it a required parameter so the choice is explicit.
- Never rely on colour alone: a tone is also text, an error is also a
  message, a selected state is also a mark.
- A focusable custom element draws the focus ring:
  `Modifier.monarchFocusRing(shape)` before the modifier that makes it
  focusable.

### Images

A component that shows a picture (avatar, link card, file card) follows one
convention, implemented by `internal/MonarchImage.kt`:

- The parameter is `image: Painter? = null`. Never a URL, a `Uri` or a
  `Bitmap`. A second overload may take `image: @Composable () -> Unit` when
  the app must compose the picture itself.
- Monarch adds no image loader, no networking and no caching. The app loads
  the image with its own pipeline (Coil's `rememberAsyncImagePainter`, a
  resource, a `BitmapPainter`) and passes the `Painter`.
- While the painter is `null` (loading, failed or no source) the component
  shows a placeholder: initials, an icon or a tinted tile. Failure is not an
  error state.
- The component clips the image and decides what TalkBack reads.

```kotlin
MonarchImage(
    painter = image,
    contentDescription = null,
    modifier = Modifier.size(MonarchAvatarTokens.Size),
    shape = MonarchShapeDefaults.Mark,
) { Text(initials) }
```

### Icons

Monarch bundles no icon set. A component never draws its own glyph and never
depends on `material-icons`. It takes the icon from the caller: a slot where
the app composes a `MonarchIcon`, or an `ImageVector`/`Painter` parameter
when the component must size and tint it. If a component cannot work without
a glyph (a chevron, a close mark), take it as a required parameter and say so
when you hand over.

### Experimental API

Mark a declaration that is not ready to be stable with
`@ExperimentalMonarchApi` and set `"status": "experimental"` in the
inventory. It never appears in a stable signature.

### KDoc

Every public declaration has KDoc: one sentence on what it is, what it wraps
and why, then `@param` for every parameter. `explicitApi()` is on, so every
declaration is `public` or `internal` in writing.

## 6. Previews

One file, `monarch-compose/src/debug/…/components/<family>/<name>/<Name>Previews.kt`,
in the package of the component. Previews are in `src/debug`, so they are not
part of the published library or its API.

```kotlin
@MonarchPreviews
@Composable
internal fun MonarchBadgePreview() {
    PreviewFrame {
        // every variant and state
    }
}
```

`@MonarchPreviews` shows the function in the light theme, the dark theme and
at the largest font size. The function is `internal` and its name ends with
`Preview`. Do not register it: `ComponentPreviewsTest` finds every
`*Previews.kt` file and composes the functions in it, and `SourceRulesTest`
fails when a component folder has no previews file.

## 7. Tests

One file, `monarch-compose/src/test/…/components/<family>/<Name>Test.kt`, in
the package `com.rookhq.monarch.components.<family>`, with two things in it.

**Fixtures.** An object named `<Name>Fixtures`:

```kotlin
internal object MonarchBadgeFixtures : ComponentFixtures {
    override val id = "badge"
    override val fixtures = listOf(
        fixture("every tone, subtle") { /* … */ },
        fixture("long text") { MonarchBadge(text = "Waiting for a second approval from finance") },
    )
}
```

`id` is the inventory id. Do not register the object: Gradle finds every
`object … : ComponentFixtures` under `src/test` and generates the registry.
`ComponentMatrixTest` then shows each fixture in all four themes, each at the
default font size, at font scale 2.0 and right to left, and fails when
composition throws, when nothing is laid out, or when an enabled element that
takes a tap has a touch target under 48dp.

Fixtures must cover every variant, size, tone and state (disabled, loading,
error, empty, long text). Several small fixtures are better than one large
one, because the failure message names the fixture. A fixture has no theme
and no scrolling of its own.

The matrix composes each fixture in a test window of 320 by 470dp. A fixture
taller than that gets its last children squashed to 0dp, which then fail the
48dp target check: keep each fixture short, and split a tall one into
several.

**A test class** named `<Name>Test` (the fast loop finds it by that name),
with `@RunWith(RobolectricTestRunner::class)` and
`createComposeRule()` from `androidx.compose.ui.test.junit4.v2`, covering:

- semantics: the role, the name, each state (`assertIsOn`, `assertIsSelected`,
  `assertIsNotEnabled`, `stateDescription()`, live region, heading, error);
- behaviour: callbacks fire when enabled and do not fire when disabled or
  loading;
- the colour logic: every pure function in `<Name>Tokens.kt`, in `AllThemes`;
- the 48dp target of each tappable part, with
  `assertTouchTargetAtLeast48dp`;
- right to left, with `assertIsBefore`, for every start or end placement;
- font scale 2.0, with `assertTextFullyVisible`, for text that could be cut;
- built-in strings: the default and the override.

A test that shows an indeterminate indicator or another endless animation
sets `rule.mainClock.autoAdvance = false` before `setMonarchContent` and
calls `rule.mainClock.advanceTimeByFrame()`. With the clock paused, a state
change made by the test itself (`expanded = true`) is seen by Compose only
after `Snapshot.sendApplyNotifications()`; call it before advancing the
frames.

**Compiled examples.** Every `examples[].code` in your inventory file is
compiled into the unit tests and composed by `InventoryExamplesTest`. You
write no test for this.

## 8. The catalogue page

`sample/src/main/kotlin/com/rookhq/monarch/sample/sections/<family>/<Name>Section.kt`:

```kotlin
package com.rookhq.monarch.sample.sections.datadisplay

/** The catalogue page of Badge. */
object MonarchBadgeSection : CataloguePage {
    override val title = "Badge"

    @Composable
    override fun Content() {
        // Composables in a column. No scrolling, no padding, no title: the catalogue adds them.
    }
}
```

The file name is the object name. The family in the navigation is the folder.
Gradle generates the list of families and pages; do not edit `CatalogueApp`.
Use `CatalogueCaption("…")` for a heading inside the page and
`CatalogueIcons` for an icon. The page should be interactive where the
component is, with `rememberSaveable` state. `CataloguePagesTest` composes
every page in the four themes.

## 9. The inventory file

`inventory/<id>.json` is the component's documentation. `components.json` is
generated from all of them. The file is validated against
`inventory/schema.json`; unknown fields are rejected. The schema is the same
as on iOS.

| Field                       | Content                                                                                                                                                                                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                        | The web id. Equal to the file name.                                                                                                                                                                                                                  |
| `name`                      | The Kotlin declaration (`android.name`), or `null` when nothing is shipped.                                                                                                                                                                          |
| `title`                     | `title` from parity.json.                                                                                                                                                                                                                            |
| `family`                    | `family` from parity.json, unchanged (`data-display`, not `datadisplay`). `foundations` for entries without a web id.                                                                                                                                |
| `category`                  | `A` native adoption, `B` wrapper or style over a Material 3 component, `C` custom.                                                                                                                                                                   |
| `coverage`                  | `android.coverage` from parity.json. If you find the plan is wrong, write what you built and say so when you hand over.                                                                                                                              |
| `kind`                      | `wrapper`, `style`, `custom`, `modifier`, `native`, `recipe` or `none`. On Android a composable over a Material 3 component is `wrapper`; `style` is for a value passed to one (a `ButtonColors`, a `Shape`); `modifier` for a `Modifier` extension. |
| `wrapsNative`               | The exact Compose or Material 3 API underneath, with its package. `null` only for `web-only`.                                                                                                                                                        |
| `status`                    | `available`, `experimental`, `planned` or `deprecated`.                                                                                                                                                                                              |
| `since`                     | The version that adds it. Entries from before the unified version say `0.1.0`.                                                                                                                                                                       |
| `summary`                   | One sentence: what it is.                                                                                                                                                                                                                            |
| `whenToUse`, `whenNotToUse` | One or two sentences each. Name the alternative.                                                                                                                                                                                                     |
| `api`                       | The public signatures, copied from the source, one string each.                                                                                                                                                                                      |
| `options`                   | One object per parameter: `name`, `type`, `default` (`"required"` if none), `description`.                                                                                                                                                           |
| `states`                    | One object per state: `name`, `description` of what changes.                                                                                                                                                                                         |
| `appearance`                | How it looks in light, dark and high contrast. One or two sentences, naming the colour roles in words.                                                                                                                                               |
| `platformNotes`             | How it differs from iOS and the web, and why. Say what the web has that this does not offer.                                                                                                                                                         |
| `accessibility`             | Concrete behaviours, one per string. Only what the code does and a test shows.                                                                                                                                                                       |
| `edgeCases`                 | Long text, empty values, extremes, things that surprise.                                                                                                                                                                                             |
| `tests`                     | The test classes that cover it: `<Name>Test`, `ComponentMatrixTest`, `InventoryExamplesTest`, `ComponentPreviewsTest`.                                                                                                                               |
| `examples`                  | Objects with `title` and `code`; optional `setup` and `imports`. See below.                                                                                                                                                                          |
| `webEquivalent`             | The React component name, or `null`.                                                                                                                                                                                                                 |
| `dependsOn`                 | Inventory ids it builds on, as in parity.json.                                                                                                                                                                                                       |

**Examples.** `code` is the body of a `@Composable` function. If it needs
state or values, declare them in `setup`; both are shown in the documentation
and placed in the same function when compiled, `setup` first:

```json
{
  "title": "A labelled checkbox",
  "setup": "var subscribed by remember { mutableStateOf(false) }",
  "code": "MonarchCheckboxRow(\n    checked = subscribed,\n    onCheckedChange = { subscribed = it },\n    label = \"Send me product updates\",\n)"
}
```

An example is code an app could write, so it can use only public API. These
are imported for you: `androidx.compose.foundation` (with `layout`, `lazy`,
`selection`, `shape`, `text`), `androidx.compose.material3`,
`androidx.compose.runtime` (with `saveable`), `androidx.compose.ui` (with
`graphics`, `graphics.painter`, `graphics.vector`, `res`, `semantics`, `text`,
`text.font`, `text.input`, `text.style`, `unit`), `com.rookhq.monarch.tokens`
and every public Monarch package, including your component's. The file opts
in to `ExperimentalMaterial3Api` and `ExperimentalLayoutApi`. Anything else
goes in `imports`, as a fully qualified name or a package followed by `.*`.

Examples are composed in all four themes at font scale 2.0, so they must not
need a network, a permission or a device capability. For an icon in an
example use `SampleIcons` (outlined Material icons from the unpublished
`monarch-sample-icons` module) and add
`com.rookhq.monarch.sampleicons.SampleIcons` to `imports`:
`MonarchIcon(SampleIcons.Search, contentDescription = null)`, or
`rememberVectorPainter(SampleIcons.Search)` where a slot takes a painter. For a
photo use `samplePainter()` (import `com.rookhq.monarch.testing.samplePainter`).
Never use `android.R.drawable.*` or the filled icons (`Icons.Default`,
`Icons.Filled`); `IconSourceRulesTest` fails on them. See `docs/PREVIEWS.md`.

When an example does not compile, the error names a file under
`monarch-compose/build/generated/monarch/test/kotlin/…/<PascalId>Examples.kt`;
the comment above each function there names the inventory file and the
example.

Write plain, factual English. Describe only what you ran. No marketing words.

## 10. The loop

From your copy of `platforms/android`, with JDK 21 and the Android SDK:

```sh
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
export ANDROID_HOME=$HOME/Library/Android/sdk

./gradlew componentCheck -Pcomponent=MonarchBadge   # the fast loop
./gradlew verifyLocal                               # everything, before handing over
```

A copy needs no `local.properties`: the SDK is found through `ANDROID_HOME`.
Copies share the Gradle daemon and the build cache, so the first build of a
fresh copy reuses compiled outputs.

`componentCheck` takes the Kotlin name, the title or the id. It validates the
inventory and the conventions and rewrites `components.json`, generates and
compiles the example sources and registries, runs detekt on your files only,
runs your `<Name>Test`, your fixtures in `ComponentMatrixTest`, your examples
in `InventoryExamplesTest`, your previews in `ComponentPreviewsTest` and the
source rules, and compiles the catalogue so your page builds.

`verifyLocal` runs detekt and lint on everything, every unit test and builds
the catalogue app. It skips what only the merge can decide: the API check,
whether `components.json` is current, the release build and publishing.

Neither is a substitute for `./gradlew verifyMonarch`, which is run on the
merged tree by `./gradlew mergeCheck`.

One test class or method on its own:

```sh
./gradlew :monarch-compose:testDebugUnitTest --tests "com.rookhq.monarch.components.datadisplay.MonarchBadgeTest"
./gradlew :monarch-compose:testDebugUnitTest --tests "*MonarchBadgeTest.coloursCome*"
```

When `generateInventory` reports a problem, the message names the file and
the rule.

## 12. Definition of done

- [ ] Only new files, at the paths in section 2. No existing file changed.
- [ ] The name is `android.name`; one public component per file, in
      `components/<family>/<name>/`; every public declaration has KDoc.
- [ ] Material 3 underneath where it has the component; a wrapper only where
      it adds value.
- [ ] Parameters in the standard order; `modifier` is the first optional
      parameter; state is hoisted; `enabled` and `interactionSource` where
      the user can act.
- [ ] No literal colour, no token colour read directly, no alpha dimming, no
      literal dp or sp.
- [ ] Start and end only. Works at font scale 2.0. 48dp touch targets,
      reserved in the layout. Reduced motion honoured.
- [ ] TalkBack role, name and state are set; nothing depends on colour alone;
      decorative icons are hidden.
- [ ] Built-in strings are in `strings_<name>.xml`, named
      `monarch_<name>_…`, and each has an override parameter.
- [ ] Pictures are `Painter?` with a placeholder; icons come from the caller.
- [ ] Fixtures cover every variant, size, tone and state.
- [ ] `<Name>Test` covers semantics, behaviour, the colour logic, touch
      targets, right to left and font scale.
- [ ] A previews file in `src/debug`.
- [ ] A catalogue page.
- [ ] `inventory/<id>.json` has every field filled truthfully, and every
      example compiles and composes.
- [ ] No new dependency. Anything the component would need is reported.
- [ ] `./gradlew componentCheck -Pcomponent=<Name>` passes.
- [ ] `./gradlew verifyLocal` passes.
- [ ] Handed over: the list of new files, anything kept private that should
      be shared, any dependency you would have needed, and anything in the
      plan entry that turned out to be wrong.
