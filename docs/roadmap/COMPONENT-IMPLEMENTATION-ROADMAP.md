# Component implementation roadmap

Scope is set by demand: a component is in scope when **3+ Rook products need
it, or 2+ need it at P0** (see
[COMPONENT-SELECTION](../architecture/COMPONENT-SELECTION.md)). Everything else
is recorded in [COMPONENT-GAP-ANALYSIS](../architecture/COMPONENT-GAP-ANALYSIS.md)
and revisited when another product needs it.

Implementation follows dependency order, one family per wave. Each wave is
merged only after `npm run verify`, accessibility (axe, three browsers), visual
baselines and the per-component documentation page pass.

| Wave | Family                                    | Entry                           | Focus                                                                                  |
| ---- | ----------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------------- |
| 1    | Foundations, actions, forms, data display | root                            | Formatters, segmented controls, tag input, copy, search, status badge, avatar, tabs    |
| 2    | Overlays and feedback                     | root                            | Confirm dialog, sheet, responsive dialog, error pages, notices, toast, brand theming   |
| 3    | Pickers and scheduling                    | root + `/scheduling`            | Entity picker, combobox, date and time pickers, time zones, calendar views             |
| 4    | Data                                      | `/data`                         | Data table, bulk actions, filter bar, saved views, command palette, reorderable list   |
| 5    | Charts                                    | `/charts`                       | Chart frame, line, bar and donut charts, sparkline, delta indicator                    |
| 6    | Collaboration and workflow                | `/collaboration`                | Activity timeline, audit log, messages, mentions, notifications, kanban, file upload   |
| 7    | Rook app shell                            | `/shell`                        | App shell, navigation rail, space and workspace switchers, theme toggle, support panel |
| 8    | Patterns and templates                    | `/patterns`                     | Record header, settings sections, schema-driven form, inbox layout, marketing blocks   |
| 9    | Editor (separate entry)                   | `@rookcom/monarch-react/editor` | Rich text editor, message composer                                                     |

Runtime brand theming (`deriveTheme`) lets a surface take a customer's brand
colour and still pass contrast; it lives in `@rookcom/monarch-tokens`.

## Wave membership

Generated by `npm run docs:generate` from
[`registry/roadmap-waves.json`](../../registry/roadmap-waves.json), the single
source for wave, package and entry point. "Below the rule" are components
named above that fewer than 3 products (or 2 at P0) need, such as the chart
frame or the PIN input; they ship with their family. The two in-scope
components already complete (`pagination`, `text-field`) have no wave.
