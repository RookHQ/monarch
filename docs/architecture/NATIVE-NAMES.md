# Native shared names

The names that the Android and iOS libraries share for the same concept, and how they differ on purpose. The table is checked: `scripts/native/status-check.mjs` (`npm run native:status:check`) reads the **Checked names** section of this file.

Rule: where two names compete, the name in the backlog proposal wins, and the web name breaks a tie. Platform idiom stays where the two languages differ: the case style of enum cases, `is`-prefixed Swift Booleans, Swift argument labels. The shared vocabulary (variants, tones, booleans) is in [NATIVE-PLATFORMS](NATIVE-PLATFORMS.md#shared-vocabulary).

How the check reads the table:

- the Android name must appear in `platforms/android/inventory/<id>.json` (`api` or `name`);
- the iOS name must appear in `platforms/ios/inventory/<id>.json` (`api` or `name`);
- a retired name must not appear in that id's inventory entry on either platform.

Separate several retired names with a comma. A `-` in the id column means the row is documentation only and is not checked. A change to a name changes the table in the same commit.

## Time zone parameters, by id

Component parameters for these ids are the IANA id `String?` on Android and Foundation `TimeZone?` on iOS (`nil` is the device zone on both). A time zone that is a field of a stored or sent model stays an IANA `String` on both:

activity-timeline, agenda-list, ai-artifact-versions, ai-computer-view, ai-conversation-list, ai-memory-panel, ai-spend-cap, ai-subagent-tree, approval-timeline, calendar-month-view, event-popover, gantt-timeline, incident-timeline, period-selector (also `MonarchPeriodSelectorDefaults.today(timeZone:)`), roadmap, running-timer, shift-roster, thread-panel, time-grid, time-off-panel, version-history-panel, virtual-message-list, webhook-deliveries.

`ai-message` and `ai-thread` also take `String?` on Android. Model `String` fields: business-hours-editor (`MonarchBusinessHoursValue.timeZone`) and slot-picker.
