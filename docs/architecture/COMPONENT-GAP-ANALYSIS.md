# Component gap analysis

Every in-scope component compared with what Monarch exports today. All tables
are generated by `npm run docs:generate` from
[`registry/components.json`](../../registry/components.json), which is built
from [`registry/component-demand.json`](../../registry/component-demand.json)
and the package manifest. Monarch version compared: the
`@rookcom/monarch-react` manifest in this repository (`monarchReactVersion` in
the registry).

## Classes

"In scope" means 3+ products need it, or 2+ need it at P0 (see
[COMPONENT-SELECTION](COMPONENT-SELECTION.md)). "Roadmap" entries are below
that rule but are named in the roadmap, mostly as parts of an in-scope family.
"Shipped" entries are current exports below the rule.

Product business logic is never a gap: it stays in the product and never
enters Monarch.
